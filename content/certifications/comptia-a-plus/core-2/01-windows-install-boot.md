## 1.1 Минимални системни изисквания

| ОС | Processor (процесор) | RAM | Storage (диск) | Друго |
|---|---|---|---|---|
| Windows 10 (32-bit) | 1 GHz | **1 GB** | **16 GB** | — |
| Windows 10 (64-bit) | 1 GHz | **2 GB** | **20 GB** | — |
| **Windows 11 (само 64-bit)** | **1 GHz, 2 ядра** | **4 GB** | **64 GB** | **TPM 2.0**, UEFI със **Secure Boot** |

🎯 **32-битова (x86) ОС вижда максимум 4 GB RAM.** 64-битовият Windows отказва 32-битови драйвери, защото драйверите работят в Kernel Mode.

## 1.2 💿 ISO, Image и DLL
- **.iso** (от файловата система **ISO 9660**) — дисков образ, симулиращ оптичен диск (CD/DVD/BD). Така се разпространяват ОС. Днес се **Mount-ва (монтира)** виртуално или се „изпича“ на зареждаща USB флашка (напр. с Rufus).
- **Image (дисков образ)** — секторно копие на цял носител: файлове, файлова система, **MBR/GPT** сектори, скрити дялове. Формати: .wim, .img, .vmdk, .gho, .iso. Позволява бързо разгръщане на много системи.
- **DLL – Dynamic Link Library (динамично свързвана библиотека)** — споделен код, който много програми използват едновременно („общият рафт с подправки“ в кухнята). Пести памет — функциите се зареждат само при нужда.
  - **„DLL Hell“** — нова програма презаписва споделен DLL и стара програма спира да работи („Runtime Error“, „Component not found“).
  - Модерно решение: **Side-by-Side (SxS) Assembly** — папката `C:\Windows\WinSxS` пази няколко версии на един DLL.

## 1.3 🔧 Методи за инсталиране на Windows

| Метод | Описание | Данни |
|---|---|---|
| **Clean Install (чиста инсталация)** | Инсталиране върху празен/форматиран диск — нова машина, тежко заразяване | ❌ Губят се (без Backup) |
| **Upgrade (надграждане)** | Стара → нова версия (Win 10 → 11) | ✅ Запазват се файлове, настройки, програми |
| **Image Deployment (внедряване чрез образ)** | Образ от **Reference / Master Machine (еталонен компютър)** се записва на много еднакви машини | — |
| **Remote Network Installation (мрежова инсталация)** | Зареждане през мрежовата карта чрез **PXE – Preboot Execution Environment** от централен сървър | — |
| **Zero-touch Deployment (внедряване без докосване)** | Напълно автоматично — **Windows Autopilot**, **SCCM / MECM**. Лаптопът се праща директно на служителя | — |
| **Recovery Partition (възстановяващ дял)** | Скрит фабричен дял (напр. F11) → връщане към фабрични настройки | ❌ Изтриват се |
| **Repair Installation / In-place Upgrade (поправяща инсталация)** | Инсталаторът се пуска от работещия Windows и подменя повредените системни файлове | ✅ Запазват се |
| **Third-party Install (чрез външен софтуер)** | Acronis, Clonezilla, SmartDeploy | — |

## 1.4 💽 Подготовка на нов диск (правилна последователност)
1. **Initialize (инициализиране)** — записва се MBR или GPT таблица.
2. **Partition (разделяне на дялове)** — създава се Volume (том).
3. **Format (форматиране)** — избира се файлова система (NTFS, exFAT…).
4. **Assign Drive Letter (задаване на буква)** — напр. E:.

## 1.5 🚀 Процесът на стартиране (Boot Process)
1. **Power On** — PSU подава захранване.
2. **Power Good Signal (PWR_OK)** — напреженията са стабилни.
3. **BIOS/UEFI Initialization** — CPU изпълнява фърмуера.
4. **POST – Power-On Self-Test (самотест при включване)** — CPU, RAM, GPU, клавиатура, дискове.
5. **Boot Device Detection** — според **Boot Order (реда за зареждане)**.
6. **Read Boot Information** — Legacy BIOS чете **MBR**; UEFI чете **ESP – EFI System Partition**.
7. **Execute Boot Loader (зареждаща програма)**.
8. **Windows Boot Manager** (`bootmgr` / `bootmgfw.efi`) чете **BCD – Boot Configuration Data**.
9. **Windows Loader** (`winload.exe` / `winload.efi`).
10. **Kernel (ядро)** — `ntoskrnl.exe`.
11. **HAL – Hardware Abstraction Layer (слой за хардуерна абстракция)** и критичните драйвери.
12. **Session Manager** — `smss.exe`.
13. **Windows Services** — `services.exe`.
14. **Logon** — `winlogon.exe`, екран за вход.
15. Автентикация → 16. Профил → 17. `explorer.exe` (Desktop, Taskbar, Start) → 18. Готово.

- **boot.ini** — стар файл за зареждане/dual-boot; **заменен от BCD**.

| | MBR – Master Boot Record | GPT – GUID Partition Table |
|---|---|---|
| Фърмуер | BIOS (Legacy) | **UEFI** |
| Местоположение | Първият сектор на диска | Зарежда се от ESP |
| Възможности | Ограничени дялове | Много и големи дялове, по-надежден |

## 1.6 🧠 Kernel (ядро)
„Сърцето и мозъкът“ на ОС — „правителството“, което разпределя ресурсите между хардуера („фабриките“) и приложенията („гражданите“).

**4 основни задачи:**
- **Memory Management (управление на паметта)** — изолира паметта на програмите (Memory Protection).
- **Process Management (управление на процесите)** — Scheduling (планиране) на процесорното време.
- **Device Management (управление на устройствата)** — чрез драйверите.
- **File System Access (достъп до файловата система)**.

| | User Mode (потребителски режим) | Kernel Mode (режим на ядрото) |
|---|---|---|
| Кой живее тук | Приложенията | Ядрото и критичните драйвери |
| Достъп до хардуера | Само чрез **System Call (системно извикване)** | Пълен |
| При срив | Само приложението се затваря | ⚠️ **BSOD** |

## 1.7 ⚙️ Process, Thread, Service

| Понятие | Аналогия | Описание | Управление |
|---|---|---|---|
| **Process (процес)** | „Офисът“ | Работеща програма със **собствена, изолирана памет**; обикновено има GUI; стартира се от потребителя | **Task Manager → End Task** |
| **Thread (нишка)** | „Работниците“ | Работникът в процеса; нишките **споделят паметта** на процеса | Windows Scheduler — ръчно не се управляват |
| **Service (услуга)** | „Поддръжката на сградата“ | Фонов процес **без GUI**; стартира се **преди логване**; системни акаунти (SYSTEM, LOCAL SERVICE, NETWORK SERVICE) | **services.msc** |

- 🎯 Забило приложение → **затваряш процеса** (End Task). Системна функция не работи (напр. печат) → **рестартираш услугата** (Print Spooler).
- 💡 **svchost.exe (Service Host)** — споделен процес-„контейнер“, в който работят много услуги.
- Примери за услуги: **Print Spooler**, **Windows Update**, **Windows Audio**.
