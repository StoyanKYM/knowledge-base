## 17.1 📘 Основни понятия
- **Virtualization (виртуализация)** — създаване на софтуерна (виртуална) версия на физически ресурс (сървър, съхранение, мрежа, ОС), така че една физическа машина да изпълнява **няколко изолирани среди едновременно**. „Сърцето на Cloud Computing.“
- **VM – Virtual Machine (виртуална машина)** — изолирана среда, която се държи като отделен компютър със собствен CPU, памет, мрежа и съхранение.
- **Host (хост)** — физическата машина; **Guest (гост)** — виртуалната ОС.
- **Hypervisor / VMM – Virtual Machine Manager (хипервайзор / мениджър на виртуални машини)** — **софтуер**, който разпределя физическите ресурси (CPU, RAM, диск) между VM-ите; „емулира“ машина, така че ОС не разбира, че е виртуализирана.

| | Type 1 — Bare-Metal (върху „голия“ хардуер) | Type 2 — Hosted (хостван) |
|---|---|---|
| Работи върху | **Директно хардуера** — функционира като ОС | **Съществуваща ОС** (Windows, macOS, Linux) |
| Производителност | По-висока | По-ниска |
| Примери | **Hyper-V, VMware ESXi / vSphere, XenServer** | **VirtualBox, VMware Workstation, Parallels** |
| Употреба | Големи компании, Data Centers | Тестване, обучение, десктоп |

🎯 **Можете да дадете на VM само ресурсите, които реално имате; хардуерните ресурси се споделят.**

## 17.2 ✨ Предимства
- **System Independence (системна независимост)** и **изолация** — проблем или пробив в VM не засяга хоста.
- Без виртуализация ОС е **тясно свързана с хардуера** — Single Point of Failure (единична точка на отказ).
- С виртуализация ОС е **преносим файл (VM Image – образ на VM)**, съдържащ ОС и приложенията → лесно преместване, архивиране и възстановяване.
- **Snapshot (моментна снимка)** — запазено състояние на VM за бързо връщане (Checkpoint).
- По-малко физическо място, захранване и охлаждане; по-висока наличност.

**Употреби на VM:**
- Хостване на сървъри;
- **Application Virtualization (виртуализация на приложения)**;
- Хостване на десктопи в облака (VDI);
- **Sandboxing (пясъчник)** — изолирана среда за безопасен анализ на зловреден софтуер;
- **Cross-platform Virtualization (междуплатформена)** — тестване на софтуер на различни ОС;
- **Training/Lab Environments (обучение и лаборатории)** — Snapshots за повторяеми упражнения.

**Application Virtualization (виртуализация на приложения):**
- **Server-based / Terminal Services (сървърна)** — приложението работи на сървъра; достъп чрез **RDP** или Citrix.
- **Client-based / Application Streaming (клиентска / стрийминг)** — приложението се пакетира и стриймва към компютъра в Sandbox (напр. **Microsoft App-V**).

## 17.3 🎭 Virtualization vs Emulation (виртуализация срещу емулация)

| | Virtualization (виртуализация) | Emulation (емулация) |
|---|---|---|
| Как работи | Виртуален екземпляр на **същия тип** хардуер | Софтуер **имитира друга система** и превежда в реално време |
| Скорост | **По-бърза и ефективна** | По-бавна |
| Пример | Windows VM на x64 хост | Super Nintendo/Android игри на Windows |

## 17.4 📋 Resource Requirements (изисквания)
- CPU с **VT-x (Intel) / AMD-V (AMD)** — активирайте в BIOS/UEFI; без тях VM-ите са много бавни.
- **SLAT: EPT (Intel) / RVI (AMD)** — по-бърза виртуална памет.
- Многоядрени процесори, Hyper-Threading и няколко физически процесора подобряват производителността.
- Достатъчно RAM, съхранение и мрежови ресурси.
- 🎯 **ARM процесорите не могат да хостват x86/x64 VM** — само ARM-базирани.

## 17.5 🛡️ Security Requirements (изисквания за сигурност)

| Атака / проблем | Описание |
|---|---|
| **VM Escape (бягство от VM)** | Атакуващият излиза от VM и достига хипервайзора/хоста (уязвимост в хипервайзора) |
| **VM Hopping (прескачане между VM)** | Преминаване от една VM в друга на същия хост |
| **Sandbox Escape (бягство от пясъчника)** | Заобикаляне на изолацията (напр. на браузъра) за достъп до привилегировани системи |
| **VM Sprawl (неконтролирано разрастване)** | Неуправлявано създаване на VM-и без контрол → незакърпени и забравени машини |

🎯 Хипервайзорът трябва винаги да е **актуален, закърпен и сигурно конфигуриран**.

## 17.6 📦 Containers (контейнери)
- **Containerization (контейнеризация)** — виртуализация **на ниво ОС**: контейнерите **споделят ядрото (Kernel) на хост ОС**, но всеки има собствено **User Space (потребителско пространство)**, библиотеки и приложения. **Няма хипервайзор.** Почти винаги под **Linux**.
- **Container (контейнер)** — съдържа всичко за изпълнение на приложението: **код и зависимости**; стандартизирана единица софтуер. Контейнерите не знаят един за друг (свързват се чрез виртуална мрежа).
- **Container Image (образ)** — лек и преносим. **Docker** — основната технология; **Dockerfile** описва как се изгражда контейнерът.
- Идеални за **Microservices (микроуслуги)**: бързо стартиране, висока плътност, **Blue-Green/Canary** внедряване, Health Probes, Sidecars.

| | Virtual Machine | Container |
|---|---|---|
| Ниво на виртуализация | **Хардуер** (чрез хипервайзор) | **ОС** (споделено ядро) |
| Изолация | Цели машини | Процеси |
| ОС | Пълна ОС във всяка VM | Споделена ОС; само приложението |
| Размер / стартиране | Голям, бавен | **Малък, светкавично бърз** |
| Ресурси | Повече RAM/CPU | **По-малко** |
| Управление | Кърпене на гост ОС | Без гост ОС |
| Преносимост | ✅ | ✅ (по-малки файлове) |

## 17.7 🧱 HCI – Hyperconverged Infrastructure (хиперконвергентна инфраструктура)
Софтуерно дефинирана инфраструктура, която виртуализира всички елементи: **Compute (хипервайзор)**, **Software-Defined Storage (софтуерно дефинирано съхранение)** и **Software-Defined Networking**.
