## 14.1 🧱 TCP/IP модел
**Protocol (протокол)** — набор от правила за структуриран обмен на данни. Устройствата използват **TCP/IP** в LAN и WAN.

| Слой | Функция |
|---|---|
| Link / Network Interface (свързващ / мрежов интерфейс) | Поставя Frames (кадри) върху физическата среда (мед, оптика, радио) |
| Internet (интернет) | Адресира пакетите и ги маршрутизира (IP) |
| Transport (транспортен) | Как се изпращат пакетите — **TCP или UDP** (Layer 4) |
| Application (приложен) | Протоколи от високо ниво (HTTP, DNS, SMTP…) |

- **Encapsulation (инкапсулация)** — данните се „опаковат“ на слоеве като плик в плик.
- **MTU – Maximum Transmission Unit (максимален размер на пакета)**.
- Аналогия: **IP адрес = адресът на сградата; Port (порт) = номерът на стаята; MAC адрес = „ЕГН-то“ на конкретното устройство в стаята.**
- **Socket (сокет)** = IP адрес + номер на порт.

## 14.2 🤝 MAC и IP заедно — ARP
- **ARP – Address Resolution Protocol (протокол за разрешаване на адреси)** — съпоставя IP с MAC. Компютърът пита: „Кой има IP 192.168.1.5? Кажи ми MAC адреса си!“ Резултатите се пазят в **ARP Table (ARP таблица)**.
- Switch поддържа **MAC Address Table (таблица с MAC адреси)** — „на порт 1 е MAC AA“.
- Router гледа IP, за да реши дали пакетът остава локално; при излизане сменя MAC „опаковката“.
- 🎯 **IP = логически адрес за Routing (маршрутизация) между мрежи; MAC = физически адрес за Delivery (доставка) в локалната мрежа.**

## 14.3 4️⃣ IPv4
- **32-битов** адрес в **Dotted-Decimal Notation (десетична нотация с точки)** — 4 **Octets (октета)** по 8 бита, всеки от 0 до 255 (напр. 192.168.1.4).
- Две части: **Network Portion (мрежова част)** и **Host Portion (хост част)**, определени от **Subnet Mask (подмрежова маска)** (напр. 255.255.255.0).

**Задължителна конфигурация на клиент:**
- **IP Address (IP адрес)** — уникален идентификатор в мрежата;
- **Subnet Mask (подмрежова маска)** — коя част е мрежата и коя е хостът; без нея устройството не знае кой трафик е локален;
- **Default Gateway (шлюз по подразбиране)** — IP на рутера в същата подмрежа; там отива трафикът извън нея;
- **DNS Server (DNS сървър)** — преобразува имена в IP адреси.

### 🗂️ Classful vs Classless
- **Classful (класова адресация)** — Класове A–E по първия октет, с фиксирана маска; водеше до загуба на адреси.
- **CIDR – Classless Inter-Domain Routing (безкласово маршрутизиране)** — гъвкаво разделяне чрез CIDR нотация (напр. /24).

| Клас | Диапазон на първия октет | Частен диапазон (RFC 1918) | Предназначение |
|---|---|---|---|
| A | 1–126 | **10.0.0.0 – 10.255.255.255** | Много големи мрежи |
| B | 128–191 | **172.16.0.0 – 172.31.255.255** | Средни мрежи, университети |
| C | 192–223 | **192.168.0.0 – 192.168.255.255** | SOHO |
| D | 224–239 | — | **Multicast (групово излъчване)** |
| E | 240–255 | — | Експериментални |

### ⭐ Специални IPv4 адреси
| Тип | Диапазон | Значение |
|---|---|---|
| **Public (публичен)** | Всичко извън частните/специалните | Глобално уникален, маршрутизира се в интернет; дава се от ISP |
| **Private (частен) — RFC 1918** | 10.x.x.x, 172.16–31.x.x, 192.168.x.x | Само в LAN; излиза в интернет чрез **NAT** |
| **Loopback (обратна връзка)** | **127.0.0.1** (127.0.0.0/8), `localhost` | 🎯 `ping 127.0.0.1` тества дали **TCP/IP стекът** на ОС работи. Ако се провали, проблемът е в ОС, а не в кабела или рутера |
| **APIPA – Automatic Private IP Addressing (автоматична частна адресация)** | **169.254.0.0 – 169.254.255.255** | Самоназначен при **неуспех да се свърже с DHCP**; работи само локално, без интернет |
| Network Address (мрежов адрес) | Първият в диапазона | Идентифицира самата мрежа |
| Broadcast Address (адрес за излъчване) | Последният в диапазона | Данни към всички устройства в мрежата |

- 🎯 **169.254.x.x** → „Мрежовата карта работи и кабелът е включен, но **няма комуникация с DHCP сървъра**.“
- **NAT – Network Address Translation (транслация на мрежови адреси)** — много устройства споделят **един публичен IP**; разшири живота на IPv4.
- **Zero Configuration – ZeroConf** — модерна алтернатива на APIPA: частен IP + **Name Resolution (разрешаване на имена)** + **Service Discovery (откриване на услуги)**.

## 14.4 6️⃣ IPv6
- **128-битов**, в **Hexadecimal (шестнадесетичен)** запис; практически неизчерпаем, по-ефективен и по-сигурен. **Не използва Subnetting** (за адреси); DNS става още по-важен.
- **Dual Stack (двоен стек)** — IPv4 и IPv6 работят едновременно на едно устройство.

| Тип | Префикс | Описание |
|---|---|---|
| **Global Unicast (глобален едноадресен)** | **2000–3999 (2000::/3)** | Като публичен IPv4 — глобално маршрутизируем |
| **Link-local (локален за връзката)** | **FE80::** | Като частен; **автоматично на всеки IPv6 интерфейс**; конфигурира се чрез **SLAAC – Stateless Address Autoconfiguration** |
| **Multicast (групов)** | **FF** | Към няколко устройства едновременно |
| **Anycast** | Без отличителен префикс | Към **най-близкото** устройство от група |

🎯 **fe80::** адресът е **нормален** (IPv6 винаги има такъв за Neighbor Discovery). **APIPA е IPv4 аналогът на Link-local**, но показва проблем.

## 14.5 🔄 TCP vs UDP

| | TCP – Transmission Control Protocol (протокол за управление на предаването) | UDP – User Datagram Protocol (протокол за потребителски дейтаграми) |
|---|---|---|
| Тип | **Connection-oriented (с установяване на връзка)** | **Connectionless (без връзка)** — „Fire and Forget“ |
| Единица данни | **Segment (сегмент)** | **Datagram (дейтаграма)** |
| Гаранция за доставка | ✅ Потвърждение (ACK), повторно изпращане, правилен ред | ❌ |
| Скорост | По-бавен | **По-бърз** |
| Употреба | Уеб, имейл, файлове | VoIP, стрийминг, гейминг, DNS, DHCP |
| Аналогия | Препоръчано писмо | Обикновен разговор |

**Three-Way Handshake (тристепенно ръкостискане):**
1. Клиентът изпраща **SYN**;
2. Сървърът отговаря със **SYN/ACK**;
3. Клиентът изпраща **ACK** → връзката е установена.

По време на ръкостискането се договарят **Sequence Numbers (последователни номера)** за откриване на загубени пакети; след това връзката е **Full-duplex (пълен дуплекс)**.

## 14.6 🚪 Портове
**Port (порт)** — логическа крайна точка за конкретно приложение или услуга. Общо **65 535** порта.

| Група | Диапазон | Описание |
|---|---|---|
| Well-Known Ports (известни портове) | **0–1023** | Стандартни услуги |
| Registered Ports (регистрирани) | **1024–49151** | Конкретни приложения (напр. 3389 RDP) |
| Dynamic / Private (динамични / частни) | **49152–65535** | Временни портове на клиента при отваряне на връзка |

- **Inbound Ports (входящи)** — „слушат“ за входящи връзки; **Outbound Ports (изходящи)** — динамично отваряни от клиента.
