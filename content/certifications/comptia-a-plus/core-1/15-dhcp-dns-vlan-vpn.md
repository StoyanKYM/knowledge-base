## 15.1 🏷️ DHCP – Dynamic Host Configuration Protocol (протокол за динамична конфигурация на хостове)
Автоматично назначава **IP адрес, Subnet Mask, Default Gateway, DNS Server** (и други, напр. NTP). Работи на сървър (Windows/Linux) или в рутера.

| Метод | Описание | За кои устройства |
|---|---|---|
| **Static (статичен)** | Ръчно въвеждане на IP, маска, шлюз и DNS — много работа и риск от дублиране | Сървъри, принтери, мрежово оборудване |
| **Dynamic (динамичен)** | Автоматично от DHCP — най-добрият избор за повечето устройства | Клиенти |

**Понятия:**
- **Scope (обхват)** — диапазонът от IP адреси за раздаване в дадена подмрежа (напр. 192.168.1.2–192.168.1.254); включва и изключените адреси.
- **Pool (пул)** — наличните адреси в рамките на обхвата.
- **Lease (наем)** — адресът се дава **за определено време**; при премахване на устройството адресът се връща след изтичане на наема. Клиентът подновява на интервали.
- **Reservation (резервация)** — устройство с определен **MAC адрес** винаги получава същия IP. 🎯 Предпочитайте резервации пред ръчна статична адресация за принтери, сървъри и рутери.
- **DHCP Relay (DHCP препредаване)** — услуга на рутера, която препраща DHCP Broadcast заявки към сървър в друга подмрежа (Broadcast не минава през рутери).

**DORA процес:**
1. **Discover (откриване)** — клиентът търси DHCP сървър (Broadcast);
2. **Offer (предложение)** — сървърът предлага адрес;
3. **Request (заявка)** — клиентът заявява предложения адрес;
4. **Acknowledge (потвърждение)** — сървърът потвърждава.

Ако процесът е неуспешен → **APIPA адрес (169.254.x.x)**.

## 15.2 📇 DNS – Domain Name System (система за имена на домейни)
- „Телефонният указател на интернет“ — преобразува **имена на домейни в IP адреси** и обратно; намира и услуги (напр. пощенски сървъри).
- **Йерархична и разпределена** база данни — няма сървър с всички записи. **13 групи Root сървъри** (над 1000 физически сървъра).
- За домашни потребители DNS се управлява от ISP; в корпоративна среда — от **Domain Controller (домейн контролер)** за Active Directory.

**Йерархия:**
1. **Root Level (коренно ниво)**;
2. **TLD – Top-Level Domain (домейн от първо ниво)** — .com, .org, .bg, .uk;
3. **Second-Level Domain (домейн от второ ниво)** — купува се от организацията (diontraining);
4. **Subdomain (поддомейн)** — www, mail;
5. **Host Level (ниво на хост)** — конкретно устройство.

- **FQDN – Fully Qualified Domain Name (напълно квалифицирано име на домейн)** — пълният точен адрес (напр. `www.diontraining.com.`).
- **URL – Uniform Resource Locator (унифициран локатор на ресурс)** — FQDN + протокол в началото (`https://...`).
- **TTL – Time to Live (време на живот)** — колко време записът е валиден в кеша.

**Процес на разрешаване:**
1. Проверка в **локалния DNS кеш** на компютъра;
2. Заявка към **DNS Resolver (резолвер)** — на ISP или трета страна (Google, Cloudflare); проверява своя кеш;
3. Resolver → **Root Server** → насочва към TLD сървъра;
4. **TLD Server** → насочва към авторитетния сървър;
5. **Authoritative Name Server (авторитетен сървър)** → връща IP адреса (A запис);
6. Резолверът връща IP-то и **кешира** резултата (както и компютърът);
7. Браузърът изпраща HTTP/HTTPS заявка към уеб сървъра.

| Метод | Описание |
|---|---|
| **Recursive (рекурсивно)** | Резолверът върши цялата работа и връща крайния отговор; кешира по TTL |
| **Iterative (итеративно)** | Всеки сървър дава препратка; отговорността е на клиента |

**DNS Records / RR – Resource Records (DNS записи):**

| Запис | Предназначение |
|---|---|
| **A** | Име → **IPv4** адрес |
| **AAAA** | Име → **IPv6** адрес |
| **CNAME – Canonical Name (каноничен псевдоним)** | Име → друго име (alias) |
| **MX – Mail Exchanger (пощенски обменник)** | Насочва пощата към правилния пощенски сървър |
| **TXT (текстов)** | Свободен текст; верификация на домейн и **сигурност на пощата** |

**Защита на пощата (чрез TXT записи) — срещу Spam (спам) и Spoofing (подправяне):**

| Механизъм | Описание |
|---|---|
| **SPF – Sender Policy Framework (рамка за политика на подателя)** | Списък на сървърите, **оторизирани да изпращат** поща за домейна; един запис на домейн; без криптография |
| **DKIM – DomainKeys Identified Mail (идентифицирана поща с ключове на домейна)** | **Криптографски подпис** в заглавията; публичният ключ е в DNS TXT записа; проверява целостта |
| **DMARC – Domain-based Message Authentication, Reporting and Conformance** | Надгражда SPF и DKIM; задава **политика** за неуспелите проверки (Accept / Quarantine-Spam / Reject) и отчети |

**Команди:** `nslookup` (Windows) и `dig` (Linux/macOS) — диагностика на DNS.

## 15.3 🧩 VLAN – Virtual Local Area Network (виртуална локална мрежа)
- **Логическо разделяне** на устройства в една физическа мрежа/суич — няколко мрежи на един суич, без дублиране на оборудване.
- Подобрява **сигурността** (изолира трафика) и **ефективността** (ограничава **Broadcast Domains – домейните за излъчване**).
- За комуникация между VLAN-и е нужен **рутер** (или Layer 3 суич).
- **VLAN Trunking (транкинг)** — пренася трафика на много VLAN-и по **една физическа връзка (Trunk)** между суичове, като маркира кадрите по протокола **802.1Q**.
- **Native / Default VLAN (родна VLAN)** — за немаркиран трафик (обратна съвместимост).

## 15.4 🔒 VPN – Virtual Private Network (виртуална частна мрежа)
- Разширение на частна мрежа през публична — **криптиран тунел** през интернет до **VPN Server / Exit Node (изходен възел)**. Трафикът е криптиран **само до изходния възел**.
- Предимства: скрива самоличността (IP на VPN сървъра), криптира данните, достъп до географски ограничено съдържание, сигурна връзка за отдалечени служители.
- **VPN Concentrator (VPN концентратор)** — устройство, което криптира/декриптира; често вградено във Firewall.

| Тип | Описание |
|---|---|
| **Site-to-Site (сайт към сайт)** | Свързва два офиса/локации |
| **Client-to-Site / Remote Access (клиент към сайт)** | Отдалечен потребител към корпоративната мрежа |
| **Clientless (без клиент)** | Сигурен тунел **през уеб браузъра** без допълнителен софтуер (TLS) |

| Режим | Описание |
|---|---|
| **Full Tunnel (пълен тунел)** | **Целият** трафик минава през VPN |
| **Split Tunnel (разделен тунел)** | Само корпоративният трафик минава през VPN; останалият — директно в интернет |

- **SSL – Secure Sockets Layer** — остарял; **TLS – Transport Layer Security** — съвременното криптиране (HTTPS).
