**Compute (изчисления)** — облачни услуги, които консумират CPU, памет и дисково пространство. Двата най-разпространени типа услуги са Compute Services и Networking Services.

## 5.1 💻 Azure Virtual Machines – VMs (виртуални машини)
- **IaaS** под формата на виртуализиран сървър (Windows или Linux).
- Подходящи при нужда от:
  - **пълен контрол** над Operating System;
  - изпълнение на Custom Software (собствен софтуер);
  - Custom Hosting Configurations (персонализирани конфигурации за хостинг).
- Гъвкавост на виртуализацията без закупуване на хардуер, но **клиентът конфигурира, актуализира и поддържа** софтуера.
- **Image (образ)** — шаблон за създаване на VM (може да съдържа OS и друг софтуер); с готов образ VM се създава за минути.
- **VM Series / Sizes (серии / размери)** — размерите са групирани в серии за различни цели.

**Ресурси, избирани при създаване на VM:**
- Size (размер) — предназначение, брой процесорни ядра, RAM
- Storage Disks (дискове) — HDD, SSD и др.
- Networking (мрежа) — Virtual Network (виртуална мрежа), Public IP Address (публичен IP адрес), Port Configuration (конфигурация на портове), Network Interface – NIC (мрежов интерфейс)

**Сценарии за използване:**
- **Testing and Development (тестване и разработка)** — бързо създаване и изтриване на различни конфигурации.
- **Приложения в облака** — изключване при липса на нужда и стартиране при пиково търсене.
- **Extending your Datacenter (разширяване на центъра за данни)** — VNet в Azure + VMs (напр. SharePoint).
- **Disaster Recovery** — VMs в Azure поемат критичните приложения при отказ на основния Datacenter.
- **Lift and Shift (пренасяне без промени)** — образ на физически сървър се хоства във VM почти без промени; поддръжката на OS остава отговорност на клиента.

### 💰 Ценови опции за VMs

| Опция | Описание |
|---|---|
| Pay-as-you-go (плащане според употребата) | Плащане по секунда/час, без ангажимент |
| Azure Reservations / Reserved VM Instances (резервирани инстанции) | Ангажимент за **1 или 3 години** с предплащане → до **72%** отстъпка |
| Azure Spot Instances / Spot VMs (Spot виртуални машини) | Използват **неизползван капацитет** на Azure със значителна отстъпка, но с намалени гаранции за наличност (риск от Eviction – изгонване) |
| Azure Hybrid Benefit (хибридна полза) | Използване на съществуващи лицензи за Windows Server (и SQL Server) с активен **Software Assurance** за по-ниска цена на VMs в Azure |

🎯 **Хибриден подход:** Reserved Instances за постоянния базов капацитет + Pay-as-you-go за сезонните пикове = оптимален баланс между спестявания и гъвкавост.

## 5.2 🛡️ Virtual Machine Availability Sets (набори за наличност на VMs)
- Разпределят VMs по различен физически хардуер **в един Datacenter**, за да не се изгубят всички при един отказ на захранване/мрежа или при поддръжка.
- **Update Domain (домейн за актуализация):** групира VMs, които могат да се рестартират едновременно; в даден момент офлайн е само един Update Domain. След актуализация всеки домейн има **30 минути** за възстановяване, преди да започне следващият.
- **Fault Domain (домейн на отказ):** групира VMs по общ източник на захранване и мрежов суич (физически Rack). По подразбиране VMs се разпределят в **до 3 Fault Domains**.
- 🎯 **Без допълнителна цена** — плащате само за VM инстанциите.

## 5.3 📈 Virtual Machine Scale Sets – VMSS (набори за мащабиране на VMs)
- Създаване и управление на група **идентични VMs с балансирано натоварване**.
- Броят инстанции се увеличава/намалява **автоматично** според търсенето (напр. метрики като CPU) или по график.
- **Автоматично разгръщат Load Balancer**; могат да се разпределят във Fault и Update Domains.
- Централно управление, конфигуриране и актуализиране на голям брой VMs за минути — за Compute, Big Data и Container Workloads.
- Аналогия: „флот от VMs, които изпълняват едно приложение и растат или се свиват автоматично“.

| | Availability Set | Scale Set |
|---|---|---|
| Фокус | **Наличност/устойчивост** | **Мащабиране** при промяна на натоварването |
| VMs | Може да са различни | Идентични |
| Автоматично мащабиране | Не | Да |
| Load Balancer | Не автоматично | Автоматично |

## 5.4 🚀 Cloud-Init (автоматична първоначална конфигурация)
- Инструмент за автоматично конфигуриране на **Linux VM при първото стартиране** (Provisioning) чрез **YAML скрипт**: инсталиране на софтуер, създаване на потребители, настройки.

## 5.5 🖥️ Azure Virtual Desktop – AVD (виртуален работен плот на Azure)
- Desktop and Application Virtualization Service (услуга за виртуализация на работни плотове и приложения) в облака — облачна версия на Windows от всяко място, през различни устройства, ОС и браузъри.
- **Подобрена сигурност:** централизирано управление с **Microsoft Entra ID**, MFA, гранулирани **RBAC** роли; данните и приложенията са отделени от локалния хардуер; сесиите са изолирани.
- **Multi-session (много сесии):** **Windows 10/11 Enterprise multi-session** — единствената клиентска Windows OS, позволяваща **много едновременни потребители на една VM**.

## 5.6 📦 Containers (контейнери)
- Virtualization Environment (среда за виртуализация) — изолирана виртуална среда; много контейнери на един физически или виртуален хост.
- Създават се от **Image (образ)**, който съдържа приложението и зависимостите му.
- **Не управлявате OS** на контейнера (за разлика от VM).
- **Lightweight (леки)**, създават се, мащабират и спират динамично; бързо рестартиране при срив.
- Най-популярният Container Engine е **Docker** — поддържан в Azure.

| Услуга | Описание | Кога |
|---|---|---|
| Azure Container Instances – ACI (инстанции на контейнери) | **Serverless** контейнери — без управление на сървъри/клъстери; плащате само докато контейнерът работи | Прости, бързи, краткотрайни контейнери. 🎯 **Няма** Autoscale, Custom Domains/SSL и лесен CI/CD |
| Azure Container Apps (контейнерни приложения) | Serverless контейнерна платформа с вградено мащабиране и балансиране | Микроуслуги без управление на клъстер |
| Azure Kubernetes Service – AKS (управлявана Kubernetes услуга) | Container Orchestration (оркестрация на контейнери) с Kubernetes | Сложни системи, пълен контрол; **изисква управление на клъстер** |
| Azure App Service – Web App for Containers | Напълно управлявана платформа за контейнеризирани уеб приложения | 🎯 Autoscale + Custom Domains/SSL + лесен CI/CD **без** управление на клъстер |

## 5.7 ⚡ Azure Functions (функции на Azure)
- **Event-driven, Serverless** изчислителна опция — без поддръжка на VMs или контейнери.
- **Trigger (задействане)** — събитие (REST заявка, таймер, съобщение от друга услуга) „събужда“ функцията; при липса на събития не се държат ресурси.
- Подходящи за работа, която завършва бързо (секунди или по-малко), и за Microservices (микроуслуги).
- **Автоматично мащабиране** — добър избор при променливо търсене.
- Таксуване **само за CPU времето** по време на изпълнение; ресурсите се освобождават автоматично.
- 🎯 **Stateless (без състояние) — по подразбиране:** функцията се държи сякаш се рестартира при всяко събитие. **Stateful (със състояние) = Durable Functions:** контекст се предава през функцията, за да се проследява предишна активност.
- Може да се разгърне и в не-serverless среда (VNet интеграция, пълна изолация).

## 5.8 🌐 Azure App Service (услуга за приложения)
- **Напълно управлявана PaaS**, базирана на HTTP — хостинг на Web Apps (уеб приложения), REST APIs, Mobile Back Ends (мобилни бекенди), Background Jobs (фонови задачи) без управление на сървъри.
- Езици и рамки: .NET, .NET Core, Java, PHP, Python, Node.js; **Windows и Linux**.
- Видове: **Web Apps, API Apps, WebJobs, Mobile Apps**.
- **App Service Plan (план за App Service)** — определя изчислителните ресурси и възможностите за изпълнение. Нива: **Free, Basic, Standard, Premium** (+ Isolated).
- 🎯 **App Service Plan ≠ Support Plan:** App Service Plan определя ресурсите за хостинг; Support Plan определя как получавате техническа поддръжка (вижте [12.10](12-governance-monitoring.md)).

## ⚖️ Сравнение на опциите за хостинг

| Опция | Модел | Контрол | Управление на OS | Мащабиране | Типичен сценарий |
|---|---|---|---|---|---|
| Virtual Machines | IaaS | Пълен | Клиент | Ръчно / VMSS | Lift and Shift, собствен софтуер |
| VM Scale Sets | IaaS | Пълен | Клиент | Автоматично | Идентични VMs при променливо натоварване |
| App Service | PaaS | Код + конфигурация | Доставчик | Autoscale | Уеб приложения и API |
| Container Instances | Serverless контейнери | Контейнер | Доставчик | Ограничено | Прости контейнери |
| AKS | Управлявана оркестрация | Висок | Споделено | Автоматично | Сложни контейнерни системи |
| Azure Functions | Serverless (FaaS) | Само код | Доставчик | Автоматично | Кратки задачи, задействани от събития |
