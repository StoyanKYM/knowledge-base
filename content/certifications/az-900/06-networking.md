## 6.1 🕸️ Azure Virtual Network – VNet (виртуална мрежа)
- Вашата **частна, изолирана мрежа в облака** (Private Address Space – частно адресно пространство) — аналог на мрежата в On-premises Datacenter.
- **Logical Boundary (логическа граница)**, определяща къде ресурсите могат да комуникират; осигурява IP адреси и Routing (маршрутизиране); контейнер от най-високо ниво за мрежовите ресурси.
- 🎯 **VNet е ограничена до един регион.**
- Основни възможности:
  - Isolation and Segmentation (изолация и сегментиране)
  - Internet Communications (интернет комуникация) — чрез Public IP или Public Load Balancer
  - Communication between Azure Resources (комуникация между ресурси на Azure) — VMs, App Service Environment, AKS, VMSS
  - Communication with On-premises Resources (комуникация с локални ресурси)
  - Route Network Traffic (маршрутизиране на трафика)
  - Filter Network Traffic (филтриране на трафика)
  - Connect Virtual Networks (свързване на виртуални мрежи)

## 6.2 ✂️ Subnets (подмрежи)
- **Подразделение на VNet** за организиране и изолиране на ресурси; позволяват прилагане на правила за сигурност и маршрутизиране.
- 🎯 **Ресурсите се разгръщат в подмрежи, а не директно във VNet.**
- Аналогия: VNet е сградата, подмрежите са стаите.

## 6.3 🔗 Virtual Network Peering (свързване на виртуални мрежи)
- Директна свързаност между VNets — ресурсите комуникират **сякаш са в една мрежа**.
- Работи и между региони — **Global VNet Peering (глобално свързване)**; трафикът минава по гръбнака на Microsoft.

## 6.4 🔌 Endpoints (крайни точки)

| Тип | Описание |
|---|---|
| Public Endpoint (публична крайна точка) | Публичен IP — достъпна отвсякъде |
| Private Endpoint (частна крайна точка) | Частен IP от адресното пространство на VNet |
| Service Endpoints (крайни точки на услуги) | Ограничават достъпа до PaaS услуги (Azure SQL, Storage) до конкретни VNets и оптимизират маршрута. 🎯 **Публичната крайна точка на услугата остава**; няма частен IP |
| Azure Private Link (частна връзка) | Свързва Private Endpoint (частен IP във вашата VNet) с PaaS услуга; трафикът остава в гръбнака на Microsoft. 🎯 **Премахва публичната експозиция** |

## 6.5 🌉 Hybrid Connectivity (хибридна свързаност)

**Virtual Private Network – VPN (виртуална частна мрежа)** — криптиран тунел през недоверена мрежа (обикновено интернет), свързващ доверени частни мрежи и предотвратяващ подслушване.

**VPN Gateway (VPN шлюз)** — тип Virtual Network Gateway (шлюз на виртуална мрежа), разгърнат в специална подмрежа на VNet.

| Тип връзка | Описание |
|---|---|
| Site-to-Site – S2S (сайт към сайт) | Свързва On-premises VPN устройство/шлюз с Azure VPN Gateway. Устройствата в Azure изглеждат като част от локалната мрежа; криптирано през интернет. 🎯 **Не прави PaaS крайните точки частни** |
| Point-to-Site – P2S (точка към сайт) | Защитена връзка от **отделен клиентски компютър** към VNet; клиентът инициира криптирана VPN връзка |
| VNet-to-VNet (мрежа към мрежа) | Криптирана VPN връзка между две VNets през VPN Gateways |
| Multi-site (много сайтове) | Една VPN Gateway свързана с няколко On-premises локации |
| Azure ExpressRoute | **Частна, специализирана връзка, която НЕ минава през интернет** |

### 🔀 Policy-based vs Route-based VPN Gateway

| Характеристика | Policy-based VPN (базиран на политики) | Route-based VPN (базиран на маршрути) |
|---|---|---|
| Поколение | „Старата школа“ | **Модерният стандарт** |
| Routing (маршрутизиране) | Static (статично) — по статични IP префикси/политики | Dynamic (динамично) — по IP маршрутни таблици |
| Протокол | IKEv1 | IKEv2 (и IKEv1) |
| Брой тунели | Ограничен (обикновено един S2S) | Множество |
| Point-to-Site | ❌ | ✅ |
| VNet-to-VNet | ❌ | ✅ |
| Multi-site | ❌ | ✅ |
| Съвместимост с ExpressRoute | ❌ | ✅ |

🎯 При нужда от VNet-to-VNet, P2S, Multi-site или **Coexistence (съвместно съществуване) с ExpressRoute Gateway** → **Route-based VPN Gateway**.

### 🚄 Azure ExpressRoute
- Разширява On-premises мрежата към облака на Microsoft чрез **частна връзка** с помощта на Connectivity Provider (доставчик на свързаност). Връзката се нарича **ExpressRoute Circuit (верига)**; всяка локация има своя верига.
- Осигурява частна IP свързаност на **Layer 3 (IP маршрутизиране)**.
- Свързва към Azure **и Microsoft 365**.
- По-голяма Bandwidth (пропускателна способност) и по-високо ниво на сигурност.
- **Border Gateway Protocol – BGP (протокол за граничен шлюз)** — маршрутизиращ протокол за обмен на маршрутна информация между различни мрежи (Autonomous Systems – автономни системи); използва се от ExpressRoute.

### 🧭 User-Defined Routes – UDR (дефинирани от потребителя маршрути)
- Персонализирано маршрутно правило, което **заменя маршрутизацията по подразбиране** на Azure вътре във VNet (напр. насочване на трафика през NVA/Firewall).

## 6.6 📇 Azure DNS
- Хостинг услуга за DNS домейни — Name Resolution (разрешаване на имена) чрез инфраструктурата на Azure. Записите се управляват със същите идентификационни данни, API, инструменти и таксуване като останалите услуги.

## 6.7 🛡️ Мрежова сигурност и разпределение на трафика

### 🧱 Network Security Groups – NSG (групи за мрежова сигурност)
- Virtual Firewall (виртуална защитна стена) — набор от **Allow/Deny правила** за входящ и изходящ трафик.
- Закачат се към:
  - **Subnet (подмрежа)** → правилата важат за всички ресурси в нея;
  - **Network Interface – NIC (мрежов интерфейс)** на VM → по-гранулиран контрол.
- 🎯 NSG **не предлага** централизиран stateful изходящ контрол, FQDN филтриране, Threat Intelligence, SNAT.

### 🗂️ Application Security Groups – ASG (групи за сигурност на приложенията)
- Мрежовата сигурност се конфигурира като **естествено продължение на структурата на приложението** (групиране на VMs по роля, напр. „web“, „db“) и използване на тези групи в NSG правила.

### 🔌 Network Interface – NIC (мрежов интерфейс)
- Необходим за свързване на VM към VNet; съдържа IP адреси и настройки. Позволява частна комуникация във VNet **без публичен адрес**.

### 🔥 Azure Firewall (защитна стена на Azure)
- Управлявана, **stateful** защитна стена — инспектира трафика и налага политики за сигурност (входящ и изходящ). Аналогия: охранител.
- 🎯 Централизиран stateful **изходящ** контрол, **FQDN / Category Filtering** (филтриране по домейн/категория), **Threat Intelligence** allow/deny, **SNAT**, VNet-to-VNet трафик чрез **Hub-and-Spoke (звезда)** топология.
- Не създава логически граници в мрежата (това правят VNet/Subnet).

### ⚖️ Azure Load Balancer (балансьор на натоварване)
- Разпределя входящия трафик между множество ресурси (напр. 5 уеб сървъра във VMSS). Аналогия: регулировчик.
- Подобрява наличността и мащабируемостта; премахва Single Point of Failure (единична точка на отказ).
- Служи за производителност, **не** за сегментиране или изолация.
- **Application Gateway (шлюз за приложения)** — балансиране на ниво приложение (HTTP/HTTPS, Layer 7).

### 🧰 Други мрежови услуги
- **Network Watcher (мрежов наблюдател)** — наблюдава и диагностицира мрежови проблеми; не конфигурира структура или сигурност.
- **Network Virtual Appliance – NVA (виртуално мрежово устройство)** — VM, изпълняваща мрежова функция (напр. Firewall).
- **Azure Bastion** — защитена **RDP и SSH** връзка към VMs през Azure Portal, **без публични IP адреси** на VMs.

| Компонент | Роля | Аналогия |
|---|---|---|
| VNet | Логическа граница, частно адресно пространство | Сграда |
| Subnet | Подразделение за организиране и изолация | Стаи |
| NSG | Allow/Deny правила на ниво подмрежа/NIC | Ключалка на вратата |
| Azure Firewall | Централизирана stateful инспекция, FQDN, Threat Intel | Охранител |
| Load Balancer | Разпределение на трафика | Регулировчик |
| Network Watcher | Наблюдение и диагностика | Камера |

## 6.8 ↔️ Ingress / Egress (входящ / изходящ трафик)
- **Egress (изходящ трафик)** — данни, напускащи Azure към интернет или външна мрежа.
- 🎯 **Inbound Data Transfer (входящ трансфер) е безплатен; Outbound Data Transfer (изходящ) се таксува.**
