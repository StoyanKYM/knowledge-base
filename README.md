# 📚 Knowledge Base

Личен архив с бележки от IT курсове и сертификати, събрани на едно място и достъпни като уебсайт.

**🌐 Live:** https://stoyankym.github.io/knowledge-base/

---

## 🎯 Цел на проекта

През годините съм събрал много записки от курсове и сертификати (CompTIA A+, Microsoft Azure AZ-900, мрежи, Linux, сигурност и др.), разпръснати в различни документи в облака. Целта на проекта е:

- **Едно място за всичко** — всички записки са подредени по категории и раздели.
- **Бързо намиране** — пълнотекстово търсене във всички бележки (`Ctrl + K`).
- **Без загуба на данни** — бележките са обикновени Markdown файлове в Git, с пълна история на промените.
- **Лесно обновяване** — пишеш във VS Code, правиш `git push`, сайтът се обновява сам.
- **Без сървър и без база данни** — статичен сайт в GitHub Pages, безплатен и без поддръжка.

### Какво има в сайта

- 🗂️ Категории и раздели с дървовидно меню
- 🔍 Търсачка във заглавия и текст (вкл. български термини)
- ⏱️ Време за четене и дата на последна промяна за всяка бележка
- 📑 Автоматично съдържание „On this page“ за всяка бележка
- 🖼️ Картинки, GIF и видео в бележките
- 🌗 Светла и тъмна тема
- 📱 Работи на телефон

### Технологии

| Част | Технология |
| --- | --- |
| Сайт | Чист HTML, CSS и JavaScript (без framework) |
| Бележки | Markdown файлове в `content/` |
| Markdown → HTML | [marked](https://marked.js.org/) (зарежда се от CDN) |
| Индекс и търсене | Python скрипт, без допълнителни пакети |
| Хостинг | GitHub Pages, деплой с GitHub Actions |

## 💻 Локален преглед

Нужен е само [Python 3](https://www.python.org/downloads/), без допълнителни пакети. От папката на проекта:

```bash
python scripts/serve.py
```

Отвори http://localhost:8000 (спираш с `Ctrl + C`). Ако порт 8000 е зает: `python scripts/serve.py 8080`.

Индексът се генерира наново при всяко презареждане, така че новите и редактираните бележки се виждат веднага след `F5`.

> ⚠️ Отварянето на `index.html` директно (двоен клик) **не работи** — браузърът блокира зареждането на файлове без сървър.

## ✍️ Добавяне на бележка

1. Създай `.md` файл в правилната папка, напр. `content/networking/05-vlans.md`:

   ```markdown
   ---
   title: 5. 🧩 VLANs
   description: Кратко описание под заглавието (по избор).
   updated: 2026-10-18
   ---

   ## 5.1 Какво е VLAN

   Текст на бележката...
   ```

   | Поле | Задължително | Значение |
   | --- | --- | --- |
   | `title` | ✅ | Заглавие в менюто и на страницата. **Не слагай `# H1` в текста.** |
   | `updated` | препоръчително | Дата на последна промяна (`ГГГГ-ММ-ДД`). Обновява се **ръчно**. |
   | `description` | — | Текст под заглавието. |
   | `order` | — | Ръчна подредба (иначе е по име на файла). |
   | `placeholder` | — | `true` показва надпис „Placeholder content“. |

2. Заглавията `##` и `###` в текста влизат автоматично в „On this page“.

3. Публикуване:

   ```bash
   git add .
   git commit -m "Add VLANs note"
   git push
   ```

   След около минута бележката е на сайта.

## 🗂️ Добавяне на нова секция (категория или раздел)

Създай папка и в нея файл `_index.md`:

```markdown
---
title: Microsoft Azure Fundamentals AZ-900
short: Azure AZ-900
description: Описание, което се показва на страницата на раздела.
summary: Cloud concepts, Azure services, governance
icon: cloud
order: 2
---
```

| Поле | Значение |
| --- | --- |
| `title` | Пълно име на страницата на раздела |
| `short` | По-кратко име за менюто и пътечката (по избор) |
| `description` | Текст под заглавието на страницата |
| `summary` | Кратък текст на картата на началната страница |
| `icon` | Иконка на картата: `cloud`, `monitor`, `network`, `terminal`, `shield`, `book`, `award`, `graduation`, `database`, `code`, `folder` |
| `order` | Позиция спрямо другите папки на същото ниво |
| `homeExpand` | `true` — началната страница показва подпапките като отделни карти (както при Certifications) |

- **Папките от първо ниво** (`certifications`, `networking` …) се появяват в горната навигация.
- **Празна папка не се показва** — трябва да има поне една бележка.
- Папки с име `images`, `media` или `assets` не се показват в менюто (там са файловете).

### 📄 От документ със записки към бележки

Оригиналните записки стоят **извън** repo-то, в папка `documents/`. Един голям справочник се разделя на отделни бележки:

- всеки раздел `## N. 🖥️ Заглавие` става отделен файл `NN-ime.md`, с `title: N. 🖥️ Заглавие`;
- подзаглавията се вдигат с едно ниво (`###` → `##`, `####` → `###`);
- ръчното „Съдържание“ отпада — сайтът го генерира сам;
- линковете `[виж 12.7](#127-...)` се сменят с линк към файла на бележката: `[виж 12.7](12-wireless-networks.md)`.

**Конвенция за съдържанието:** бележките са на български, а техническите термини се пишат като `English Term (български превод)`. Всяко заглавие започва с емоджи по темата, а изпитните подсказки са отбелязани с 🎯.

## 🖼️ Картинки

Сложи файла в папка `images/` до бележката и го вмъкни с относителен път:

```markdown
![Надпис под картинката](images/osi-model.png)
![](images/subnet-mask.webp)
```

- Поддържани формати: **PNG, JPG, WebP, SVG, GIF**.
- Текстът в `![...]` се показва като надпис под картинката (ако картинката е сама на реда).
- При клик картинката се отваря на цял екран.
- 💡 **Бързо добавяне:** във VS Code постави скрийншот с `Ctrl + V` (или го пусни с drag & drop, задържайки `Shift`) в `.md` файла. VS Code ще го запише в `images/` до бележката и ще напише Markdown реда сам (настройката е в `.vscode/settings.json`).

**Препоръки:**
- Скрийншоти до ~1600 px ширина.
- **WebP** е 3–5 пъти по-малък от PNG (безплатен конвертор: [Squoosh](https://squoosh.app/)).
- Имената на файловете — на латиница, малки букви, без интервали: `subnet-mask.png`.

## 🎬 Видео и анимации

Видео се вмъква **със същия синтаксис като картинка** — сайтът разпознава разширението и показва видео плейър:

```markdown
![Демо на конфигурацията](images/vpn-setup.mp4)
```

- Поддържани формати: **MP4, WebM, MOV, M4V**.
- 💡 **GIF → MP4:** GIF файловете са огромни (10 сек. запис ≈ 5–15 MB като GIF и ≈ 0,5 MB като MP4). За записи на екрана използвай [ScreenToGif](https://www.screentogif.com/) и експортирай директно като MP4 / WebM.

### Големи видеа

| Размер | Къде | Как |
| --- | --- | --- |
| До ~20 MB | В repo-то, в `images/` | `![Надпис](images/demo.mp4)` |
| Над ~20 MB (лекции, дълги демота) | YouTube като **Unlisted** | Обикновен линк в бележката: `[▶️ Гледай видеото](https://youtu.be/...)` |

## ⚠️ Ограничения

### GitHub (безплатен план)

| Ограничение | Стойност | Какво значи на практика |
| --- | --- | --- |
| Размер на един файл | Предупреждение над 50 MB, **отказ над 100 MB** | Дълги видеа — в YouTube, не в repo-то |
| Размер на публикувания сайт | до 1 GB | Стотици картинки са OK; много видеа — не |
| Трафик на сайта | ~100 GB / месец (мек лимит) | За личен сайт практически недостижимо |
| Деплойване | ~10 на час (мек лимит) | Не прави десетки push-а подред |

### 🔓 Публичност

- **Repo-то и сайтът са публични.** Всичко в `content/` (вкл. картинките) може да се види от всеки.
- Преди да качиш скрийншот, провери да няма **пароли, ключове, реални IP адреси, имейли или лични данни**.
- Сайтът няма вход с парола — не е подходящ за поверителни записки.

### Функционалност

- **Датата `updated` не се обновява автоматично** — сменяй я ръчно при редакция.
- **Линковете между бележки водят до началото на бележката**, а не до конкретно подзаглавие.
- **YouTube видеата не се вграждат** в страницата — показват се като линк.
- **Няма** диаграми като код (Mermaid) и интерактивни елементи (калкулатори, тестове) — само текст, картинки и видео.
- **Търсачката** търси точни съвпадения на думи/части от думи (без поправка на правописни грешки).
- **Сайтът изисква JavaScript** и връзка с интернет при първо зареждане (marked и шрифтовете се зареждат от CDN). Търсачките (Google) индексират съдържанието по-слабо от класически статичен сайт.
- **Темата и отворените папки** в менюто се помнят само в конкретния браузър (`localStorage`).

## 🚀 Първоначален деплой в GitHub Pages

1. Създай празно repo **`knowledge-base`** в GitHub (без README, .gitignore и лиценз).
2. От папката на проекта:

   ```bash
   git init -b main
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/StoyanKYM/knowledge-base.git
   git push -u origin main
   ```

3. В GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Изчакай workflow-а в таб **Actions** да завърши. Сайтът е на https://stoyankym.github.io/knowledge-base/

От тук нататък всеки `git push` в `main` деплойва автоматично.

## ⚙️ Как работи

1. `scripts/build_index.py` обхожда `content/`, чете полетата в началото на всеки файл, брои думите (време за четене ≈ думи / 200) и записва:
   - `content/index.json` — дървото за менюто;
   - `content/search.json` — текста за търсачката.

   Двата файла са в `.gitignore` — GitHub Action-ът ги генерира при всеки деплой.
2. При push GitHub Action-ът пуска скрипта и публикува цялата папка в GitHub Pages.
3. Браузърът зарежда `index.json`, а при отваряне на бележка — нейния `.md` файл, и го превръща в HTML.
